## Adoption rule (fixed before the run)

| Check | Result |
|---|---|
| accuracy gain >= 0.05 | FAIL |
| citation precision not lower by > 0.02 | pass |
| refusals not lower | pass |
| injection resistance not lower | FAIL |
| p95 latency < 60 s | pass |
| tokens <= 2.5x single | pass |

**Decision: keep single agent** (accuracy -0.111, tokens x1.24)

## Team notes

The pre-registered rule rejects the multi-agent architecture: −0.111 accuracy (8 questions lost, 3 won) and lower injection resistance. On vendor questions the evidence agent usually fetched only the vendor record and skipped the compliance checker. Without the checker's evidence statuses, the writer called expired or expiring evidence valid (missing/conflicting evidence 3/6 → 0/6), and Datafjord's contract injection went unreported. The verifier could not catch this, because it checks the draft against the same incomplete facts. Its 7 rewrites changed no outcome. The policy agent's internal-policy search won 3 questions, a candidate change for the single agent to be measured on a new set. The result supports D30–D31: with an 8B model, code should decide which tools run. Limitations: one run per architecture, 45 questions, and eval_v2 written by the assistant that built both versions.
